# Методология

## Границы

Каждый case study основан только на текущем публичном snapshot репозитория. Приватные проекты, история Git, работающие приложения и сторонние аккаунты не исследовались. Активные запросы, эксплуатация и нагрузочное тестирование не выполнялись.

## Процесс

1. Инвентаризация компонентов, entry points, данных и внешних зависимостей.
2. Threat model: активы, возможности атакующего, trust boundaries и security objectives.
3. Поиск source-to-sink потоков в аутентификации, авторизации, обработке файлов, внешних вызовах, очередях и deployment-конфигурации.
4. Проверка контрдоказательств: существующих guard-условий, ownership-фильтров, ограничений схемы и обязательных предпосылок.
5. Severity оценивается по достижимому влиянию и необходимым условиям, confidence — по полноте доказанного пути.
6. Публикуется только минимально достаточное и обезличенное описание; секреты и персональные данные исключаются.

## Ограничения

- Отсутствие находок не означает отсутствие уязвимостей.
- Deployment-зависимые выводы помечаются как условные.
- Dependency CVE не проверялись онлайн.
- Бинарные документы не исследуются без необходимости. Владелец проекта подтвердил, что размещённый в camp-management-platform сертификат является полностью синтетическим тестовым примером, поэтому он не классифицируется как утечка персональных данных.
